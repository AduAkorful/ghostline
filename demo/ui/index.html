01 GET THE TOOLS

Install locally.
Keep control.

One command downloads the CLI, reference API, and MCP server. Wallet setup and funding stay on your machine.

INSTALL THE RELEASE
curl -fsSL https://raw.githubusercontent.com/AduAkorful/ghostline/main/scripts/install-ghostline.sh | sh

The installer verifies the release checksum. It does not create or fund a wallet.

02 START THE OTHER SIDE

A provider names
its terms.

Run the reference paid API, or connect an agent to a compatible provider. The service sets its price and accepted channel terms.

REFERENCE SERVICE · PLACEHOLDERS
ghostline-paid-api init --ledger /private/ledger.json --session /private/session.json …
ghostline-paid-api serve --bind 127.0.0.1:8787 --price 10 …

Use a fresh service authorization key per channel. A separate one-time payout key is optional; both keys are still visible in that channel's settlement.

03 DEFINE A CHANNEL

Choose the terms
before funding.

Compute the payer root and channel id, then write a channel file using your real deployment parameters. This step stays offline.

PREPARE · PLACEHOLDERS
ghostline spec --network-tag <tag> --deposit 100000 …
ghostline channel init --out /private/channel.json …

Never use invented template hashes or service keys. The channel file becomes sensitive after it stores a deposit mask.

04 OPEN ONCE

Review the fee.
Then open.

Dry-run through your local wallet first. A live channel open requires a reviewed, explicit fee cap and spends the deposit.

REVIEW BEFORE BROADCAST
ghostline channel open --file /private/channel.json --dry-run
# After review:
ghostline channel open --file /private/channel.json --max-fee <reviewed-cap>

The channel output is visible on the network; its stealth conditions protect some output details.

05 PAY PER REQUEST

Accept a quote.
Sign the next total.

For each HTTP 402 quote, Ghostline checks the channel terms and spending policy, then signs a cumulative voucher. No per-call transaction is sent to the chain.

REFERENCE PAYER · PLACEHOLDERS
ghostline-paid-api call --url http://127.0.0.1:8787/fortune \
  --session /private/session.json --calls 1000 \
  --vendor-hex <service-key> --budget 10000 --max-per-call 10

A cumulative voucher is an off-chain service record, not proof that every request was made.

06 CHECK BOTH RECORDS

Local totals tell
only half the story.

Read the channel state and export call accounting. Check the indexer separately for transaction results and output state.

LOCAL RECORD · NOT CHAIN PROOF
ghostline channel status --file /private/channel.json
ghostline channel calls --dir /private/channels --out calls.csv

Call details come from the service ledger. The latest claim-free Esmeralda settlement used the deployed fixed-output rule: two stealth outputs and a 1 µT payer reserve. The deposit and service amount remained unrevealed.

07 CLOSE AND VERIFY

Many accepted calls.
One settlement.

Review the result, choose to submit, then ask the indexer for finality. The latest Esmeralda test finalized one settlement while hiding the service amount from observers.

DRY-RUN → INTENTIONAL SUBMIT
ghostline channel settle --file /private/channel.json --dry-run
# Submit only after review:
ghostline channel settle --file /private/channel.json --submit
# Verify the returned transaction id:
ghostline indexer result --url <indexer-url> --transaction-id <tx-id>

The live settlement finalized on Esmeralda with no covenant claim or plaintext amounts. The latest template's fixed two-output rule was also exercised on Esmeralda. Fees and timing remain public.

↳ AN ALTERNATE ENDING

If it expires
without settlement.

When the channel remains unspent through expiry, the payer can take the refund branch. This path cannot follow a successful settlement.

EXPIRED OUTPUT ONLY · DRY-RUN FIRST
ghostline channel refund --file /private/channel.json --dry-run
# Confirm expiry and output state before intentional submission:
ghostline channel refund --file /private/channel.json --submit

A spent output cannot be refunded. The channel-file helper uses a fixed 100,000 µT fee cap.

Examples contain placeholders and are shown for explanation only. Keep keys, wallet profiles, channel masks, and service credentials on your own machine.

EXPERIMENTAL · TRUSTED-LOCAL PROTOTYPE

Two channels.
One pooled close.

On Esmeralda, two channels each recorded 20 paid calls locally, then finalized one pooled settlement with two channel inputs and three stealth outputs. The service amount was opened locally with its one-time payout key; it was not readable in the public transaction fields.

This is not coordinator-private. The local builder received both deposit values and masks, and observers can see the channels were grouped in one transaction. It is a research prototype, not a hosted or recommended production flow.

Inspect pooled settlement ↗

The explorer links open finalized Esmeralda transactions. The 20-call count and accepted total come from the local service ledger. The standard settlement transfer statement had zero covenant claims, no revealed channel amounts, and exactly two stealth outputs; separate fee instructions and fee amounts remain public, along with timing, branch, channel id, authorization data, and output commitments.

THE REST OF THE TOOLBOX

Every Ghostline command.

The tour follows one common path. The map below covers the wider CLI, HTTP payer, and MCP surface.

Channel lifecycleprepare, open, inspect, and close channel files+
  • channel-idCompute a channel identifier from the open parameters.
  • channel initWrite a channel file without contacting the network.
  • channel openOpen through a wallet, then unblind and save the output mask.
  • channel sessionCreate or resume a matching payer session.
  • channel bindBind an already opened output to a channel file.
  • channel statusReport off-chain state and observe the known output.
  • channel settle / refundSettle before expiry or refund at/after expiry, subject to channel state.
  • channel list / report / calls / traceList records, export accounting, show call prices, or assemble a privacy receipt.
  • channel watchPoll until a channel is due; it broadcasts only with --submit.
Voucher and channel toolskeys, terms, signing, and verification+
  • keygenGenerate a role-labelled Ristretto key file; use a fresh payer key for each channel.
  • specCompute the payer root and channel id from a full channel specification.
  • signSign the next cumulative voucher through a session and policy.
  • verifyVerify an encoded voucher against its channel parameters.
  • pay-toPrint the conditions JSON used for stealth channel outputs.
  • helpShow the top-level or selected subcommand help.
Wallet and output recoverylocal wallet access, discovery, and unblinding+
  • wallet key-createCreate a fresh wallet-managed service key; a second one can be used as a one-time payout key.
  • wallet openOpen a channel output through the local wallet daemon.
  • wallet utxosRead outputs from a wallet-stored transaction for inspection or binding.
  • wallet account-create / account-getCreate a named account or inspect an existing account and owner key reference.
  • wallet submitDry-run or submit an unsigned transaction through the wallet daemon.
  • unblind / unblind-txRecover an output amount and mask using the claim secret.
  • inspect-txInspect public stealth output fields without a secret.
Transaction constructionseal and prepare channel transactions+
  • seal-openSeal an open transaction from a key-path input to channel conditions.
  • seal-settleSeal a settlement against the channel output and voucher.
  • seal-refundSeal an expired-channel refund.
  • seal-unsignedSeal resolved unsigned JSON for indexer-prepared inputs.
Operator and indexerwatch, prepare, submit, and verify+
  • status / reportShow off-chain channel totals and the observer panel; not chain confirmation.
  • watchCheck the settlement window and expiry using the indexer epoch.
  • settle-due / refund-dueBuild, dry-run, or submit the ledger's latest voucher settlement or an expired refund.
  • indexer wait / epochCheck readiness and read the current epoch.
  • indexer dry-run / submitAsk the indexer to evaluate or submit a sealed transaction.
  • indexer result / resolve-inputsRead transaction finality or resolve unsigned transaction inputs.
Paid API and MCPservice setup and agent integration+
  • ghostline-paid-api init / serveInitialize and run the HTTP 402 reference service.
  • ghostline-paid-api callCall a paid endpoint with a session and policy limits.
  • ghostline-mcpRun the MCP stdio server; see the API reference for its tools and environment.

Wallet commands use the operator's local wallet endpoint; indexer commands use the configured indexer. Dry-run does not broadcast. Submit commands can move funds. Review fee caps before live actions.

THE PRIVACY BOUNDARY

Quiet to observers.
Visible to the service.

Ghostline hides the spending pattern from third parties. It does not hide activity from the service receiving payment.

01 / PAYER

Your full view

You know your calls, channel details, and the vouchers you sign. Your deposit mask stays in payer-controlled channel state during ordinary individual flows.

02 / SERVICE

Each request

The service sees its requests, prices, and voucher stream as it serves them. It knows the declared deposit limit, but does not receive the payer's deposit mask in ordinary individual flows.

03 / OBSERVER

One close record

In the tested claim-free close, observers do not see the deposit, exact service amount, or payer remainder. Fees, timing, branch, channel id, authorization data, output commitments, and output count remain visible.

KEY SEPARATION · REDUCES REUSE SIGNALS

Ghostline supports fresh payer and service authorization keys for each channel, plus an optional separate one-time service payout key. This can reduce correlation from reusing keys across channels or later spends. The authorization and payout keys are both public in the same settlement, so this does not unlink the payer and service within that transaction or hide funding and timing links.

Pooled settlement remains experimental: its coordinator sees all participating deposit openings, and the chain shows which channels were grouped. Funding patterns, timing, and who pays fees can also create correlations. Ghostline does not promise anonymity or unlinkable funding.

NO HOSTED SIGNER · NO BACKEND

Try it locally.
Keep your keys.

The website is a static explainer. Ghostline commands run on your machine; your wallet keys and credentials stay with you. Start with a no-funds local demo, then follow the Esmeralda guide if you want to make a testnet transaction.

SAFE FIRST TRY · LOCAL ONLY
git clone https://github.com/AduAkorful/ghostline.git
cd ghostline
bash scripts/quickstart-smoke.sh

This builds the reference CLI and API, uses temporary test keys, pays three local requests, then removes its temporary files. It does not contact a wallet, use Esmeralda, or submit a transaction. The first build may take a few minutes.

LINUX · x86-64 · glibcNO ROOT REQUIRED

INSTALL THE CLI, API & MCP SERVER
curl -fsSL https://raw.githubusercontent.com/AduAkorful/ghostline/main/scripts/install-ghostline.sh | sh

Installs the published v0.3.1 CLI, API, and MCP server to ~/.local/bin and verifies the release checksum. It does not set up or fund a wallet. The fixed two-output settlement rule is included in this release.

KNOW THE LIMITS

Early development.
Testnet only.

  • Ghostline is unaudited. Do not use real funds.
  • Fees are public and may exceed small-call totals.
  • The tested claim-free close hides deposit, exact service amount, and remainder; branch and output commitments remain visible.
  • Call counts are service records, not chain-attested receipts.
